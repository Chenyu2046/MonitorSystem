# P0/P1 生产化整改说明

> 范围：`codex/production-hardening` 分支，汇总至提交 `02a7856`。目标是修复已确认的生产安全、可靠性、资源边界与指标正确性问题；不引入协议 wire-format 或数据库 schema 迁移。

## 问题清单与方案

| 优先级 | 问题 | 解决方案 | 优化效果 |
| --- | --- | --- | --- |
| P0 | 默认明文 gRPC、数据库凭据风险 | 数据库和 mTLS 配置改为环境变量；缺失时启动失败；明文仅保留显式本地开关 | 生产默认 fail-closed，避免明文链路和源码秘密 |
| P0 | 仅信任 CA，证书可跨主机冒用 | Worker hostname 必须同时位于 allowlist 与客户端 SAN；查询端也校验证书 SAN | 将身份、缓存键和持久化键绑定到认证 hostname |
| P0 | RPC 字段拼接 SQL | 所有主机名、接口名、查询条件进入 SQL 前统一使用 MySQL 转义 | 消除引号、反斜杠等输入造成的 SQL 注入路径 |
| P1 | 写库失败仍可能被上游当成功 | 五表写入使用事务；失败、过载、commit 结果未知映射为非 OK gRPC 状态 | Worker 能观察持久化失败，避免伪成功 |
| P1 | 并发上报竞争采样基线，慢库导致无限等待 | 采样状态实例化并串行保护；写入锁最多等待 200ms；MySQL 连接/读/写超时均为 5 秒 | 消除数据竞争，并以有界背压替代线程堆积 |
| P1 | 动态 IP、失联主机和实时缓存可无限增长 | 状态仅以认证 hostname 建键；主机上限 256，实时缓存 TTL 60 秒 | 防止 IP 漂移与接口 churn 耗尽内存 |
| P1 | 查询可深分页、全表异常扫描、错误被伪装为空结果 | 页大小最多 1000、OFFSET 最多 100000、时间范围最多 31 天；异常查询必须指定主机；查询失败返回 `UNAVAILABLE` | 限制数据库扫描成本，区分空结果与不可用 |
| P1 | 查询返回字段不完整、同秒排名重复 | 补齐性能/趋势变化率 SQL→结构体→Proto 映射；排名以 `MAX(id)` 打破同秒并列 | 客户端不再把缺失字段误判为 0，排名与总数一致 |
| P1 | 非法时间、NaN/Inf 与派生溢出可污染 SQL | 拒绝非零 nanos、超出本机 `system_clock` 的时间；递归拒绝 NaN/Inf；聚合、变化率和窄化后再次有限值兜底 | 避免时间回绕和 `inf` 写库失败 |
| P1 | CPU/网络计数器回退、eBPF 接口删除导致错误指标或缓存残留 | CPU 总增量非正时跳过本轮百分比；网络计数器回退按新周期处理；eBPF 每轮重新校验 ifindex 并清理缓存 | 避免 NaN、无符号下溢、错误高流量和长期缓存增长 |
| P1 | 文档与运行行为不一致 | 更新运行链路、环境变量、失败语义、秒级时间契约及回滚说明 | 运维和面试说明可直接对应当前代码 |

## 关键边界

- 单次上报：最大 256 KiB；CPU/网络/磁盘/软中断列表各最多 256 项。
- 运行时状态：最多 256 个主机；实时缓存 60 秒过期。
- 查询：单页最多 1000 条，最大 OFFSET 为 100000，最大时间跨度为 31 天；趋势最小粒度为 300 秒。
- MySQL：连接、读、写超时均为 5 秒；写入和查询锁等待均限制为 200ms。

## 验证与残余项

- 已完成：多轮独立 CR、静态契约检查、`git diff --check`、无 MySQL 分支 C++ 编译、分页与锁边界检查。
